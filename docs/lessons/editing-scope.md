# 편집 범위 교훈

요약: provider에 맞는 부분 편집과 정확한 파일 이름 지정으로 기존 사용자 편집과 승인 경계를 보존한다.

## Provider별 지시

- Codex: 파일 전체 재작성 금지, 최소 부분 변경. Codex에는 Edit 도구가 없으므로 Edit 사용을 지시하지 않는다.
- Claude/Z.ai: Write로 전체 재작성 금지, Edit로 부분 교체.

이 재작성 금지는 기존 파일과 생성 후 수정 라운드에 적용한다. 승인된 미존재 새 파일의 최초 생성은 허용한다. 이후 수정은 필요한 부분만 바꾸며 기존 문장·공백·순서·권한과 사용자 편집을 보존한다. 도구가 다르다는 이유로 전체 덮어쓰기로 대체하지 않는다.

## 정확한 이름으로 지정

TASK에는 파일의 정확한 이름을 항상 쓴다. workflow는 scope를 정렬하므로 처음 N개 같은 위치 지정은 사용하지 않는다. 파일별 읽기·쓰기 의도가 있으면 각각 해당 경로에 연결한다. FILES_FILE 밖 문서를 관련성이 있다는 이유로 자동 열람하거나 추가하지 않는다.

위치 지정이 잘못 해석된 사용자 제공 관측은 'PR-1 첫 시도'로만 표기한다. 이 표현을 실제 PR #1이나 확인하지 않은 run에 연결하지 않는다. 이름 기반 지정의 필요성을 보여주는 관측으로만 남긴다.

## 이번 탐색층 적용

AGENTS.md는 지정된 탐색 문장 한 줄 추가만 허용한다. 새 wiki 12개 외에 기존 문서의 이동·분할·본문 수정은 다음 단계다. 운영 설정·개선 scope·코드·테스트·CI·Makefile을 변경하지 않는다. 기존 참조 7개는 읽기 승인 목록 밖이며 링크 안내만 사용한다.

문서 필요성이 생기면 정확한 누락 경로와 이유를 보고한다. 검토 finding은 기존 승인 파일에 귀속하고, coordinator가 범위를 확인해 새 실행을 준비한다. 수리 라운드에서 승인을 확대하지 않는다. 이번 작업은 하네스 동작 변경이 아니므로 새 ADR이나 기존 설계 본문 수정이 필요하지 않다.
