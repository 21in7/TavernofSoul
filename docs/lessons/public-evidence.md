# 공개 정보와 근거 교훈

요약: 공개 가능한 최소 사실만 쓰고 직접 확인·사용자 제공 관측·미확인을 구분한다.

## 공개 문서의 경계

credential·토큰 값/저장 위치, 홈 등 private 절대 경로, state/lock/storage 내부 경로, 운영 DB 접속 정보, 실제 요청 ID·응답 본문은 공개 저장소에 쓰지 않는다. 원문 로그·private 실행 설정·고정 조회용 호스트 경로와 식별값도 옮기지 않는다. 기존 문서의 private 예시를 복제하지 않는다.

정본 관계 설명에는 `logs/harness/harness-runbook-core.json`, parent의 설정 준비 안내에는 `logs/harness/local-model.json`만 해당 용도로 표기한다. 모델이 logs를 추가로 읽는 허가가 아니다. 실제 조회 기준값과 환경을 공개하지 않고 결과의 의미와 남은 확인 사항을 적는다.

run ID와 PR 번호는 공개 가능하지만 새로 추정하지 않는다. 확인하지 않은 run과 교훈을 연결하지 않으며, 위치 지정 오해 관측인 'PR-1 첫 시도'를 실제 PR #1로 바꾸지 않는다. 정보가 부족하면 필요한 정확한 경로와 이유만 보고하고 읽기 범위를 확대하지 않는다.

## Fork와 역할

fork 저장소의 PR compare 대상은 `21in7/TavernofSoul`이다. 원본 저장소로 보내지 않으며 compare URL을 설명할 때도 해당 fork를 기준으로 한다. 전달·복구는 [GitHub 전달](../ops/github-transport.md)의 원래 요청 연결 규칙을 따른다.

credential은 사용자만 다루며 모델에 제공하지 않는다. workflow는 세션 전체에서 동시에 하나만 실행한다. 구현자·reviewer는 검사·Git·운영 명령·재위임·workflow를 실행하지 않는다. 공개 요약은 이 경계나 기존 실행 권한을 바꾸지 않는다.

## 관측의 강도

[작업 이력](../log.md)의 날짜·제목은 제공된 로컬 Git 근거이며 날짜는 commit date다. PR별 실패·복구 교훈은 사용자 제공 관측이다. commit 제목만으로 실패 원인·테스트·CI·운영 성공까지 검증했다고 쓰지 않는다. 문서 작성자가 이번에 조회·검사했다는 표현으로 바꾸지 않는다.

직접 확인한 종료 결과, 사용자 제공 사실, 아직 미확인인 상태를 분리해 보고한다. 정상 종료 결과 없는 호출은 성공이 아니다. 과거 성공·작성한 테스트·준비 상태를 이번 검증 성공으로 표현하지 않는다. merge 성공과 cleanup/archive 완료도 각각 확인해야 한다.

문서의 의미적 완전성은 매 검토의 새 판단이다. 링크 검증이나 Markdown 확장자만으로 공개 제한과 사실성이 보장됐다고 주장하지 않는다. [실패 보고](../ops/failure-reporting.md)에 따라 pending과 한계를 남긴다.
