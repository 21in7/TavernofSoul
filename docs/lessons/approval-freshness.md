# 승인 freshness 교훈

요약: 개선 승인은 scope 전체 source fingerprint에 묶이며 한 파일이나 control 변경도 기존 승인을 무효화한다.

## 전체 scope가 승인 기준

개선 승인은 제안에서 수정할 일부 파일만이 아니라 scope 전체 source fingerprint에 묶인다. scope 안 파일 하나가 바뀌어도 모든 기존 승인이 stale이 된다. 관련이 적어 보이는 변경이라는 이유로 이전 승인을 그대로 사용하지 않는다.

control 설정 변경도 회차를 무효화한다. 진행을 유지하거나 실행을 쉽게 하려고 임의로 바꾸지 않는다. 같은 후보가 다시 보이더라도 달라진 source나 control 아래에서 이전 승인을 재사용하지 않는다. 바뀐 입력을 과거 검토 결과가 보장한다고 해석하지 않는다.

## 제안과 실행 허가의 구분

eligible 표시는 실행 허가가 아니다. 제안 ID별 사용자 승인을 유지하며 보고서의 준비 상태나 권고 문구로 이를 대체하지 않는다. 다른 제안의 승인, 이전 회차의 승인, 일반적인 개발 작업 허가를 자율 발견 제안의 실행 허가로 확대하지 않는다.

승인 기록이 있다는 사실만으로 현재 입력과 일치한다고 판단하지 않는다. parent가 전체 source와 control의 일치 및 해당 제안의 명시적 승인을 확인한다. worker/reviewer는 승인·실행을 대신하지 않으며 실행을 위해 scope나 설정을 조정하지 않는다.

## 변경을 발견했을 때

stale인 승인을 사용해 진행하지 않는다. 필요한 파일과 변경 이유를 구체적으로 보고하고 coordinator가 범위를 확인해 새 실행을 준비한다. 기존 수정 라운드는 읽기·쓰기 경계를 넓히는 수단이 아니다. 검토에서 승인 밖 문서가 필요하면 정확한 경로와 이유를 남긴다.

이번 wiki는 승인 원칙의 공개 요약이며 운영 설정·개선 scope·정책을 변경하지 않는다. 문서 변경 자체도 scope 안 파일 변경이라는 사실을 놓치지 않는다. 실제 개선 연구·승인 상세는 별도 읽기 승인이 있을 때 [improvements](../improvements.md)를 참조한다.
